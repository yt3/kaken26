\noindent\textbf{(1)本研究の学術的背景や本研究の着想に至った経緯、研究課題の核心をなす学術的「問い」}

\textbf{[背景]} 近年の\ul{大規模言語モデル（LLM）}の急速な性能向上は，利便性と引き換えにセキュリティ上の重大な問題をもたらしつつある．たとえば最新版に近い LLM である Claude Mythos Preview は，既存のソフトウェアにおける数千件の高重大度脆弱性を，短時間で自動的に発見し，さらに攻撃コードまで作成したことが報告されている．加えて単独の脆弱性だけでなく，複数の軽微な脆弱性への連鎖的な攻撃により，重大なインシデントを誘発可能であることも実証された．

これに対し現状では，セキュリティリスクを軽減させたモデルのみ公開するという，一時的な対策が取られている．ただし理想的には，すべての脆弱性を精査し，攻撃手段を確実に遮断するための修正コード，いわゆるパッチを作成して適用することが望ましいが，コスト的に非現実的である．そこで現実的には次の各課題を考慮した上で，対策を取る必要がある．
\begin{enumerate}
\item 脆弱性の重大度の多様さ：LLM が「発見した」とされる脆弱性は，実際には到達不能，あるいは既存の防御で無害なため，修正が不要なものもある．また深刻度が高くても外部から到達困難な脆弱性より，評価上は中程度でも実際に悪用される可能性が高いものを先に修正すべき場合がある．さらにそもそも脆弱ではない箇所をご検出することも多い．このような脆弱性の修正の要不要の判断，および優先順位付けを行う必要がある．

\item 連鎖的攻撃への対応：連鎖的攻撃に対しては，関係する個々の脆弱性を修正するだけでなく，一部の脆弱性の修正で連鎖を遮断できる場合や，逆に連鎖における後続の脆弱性と攻撃にも対応が必要な場合の考慮が必要である．

\item パッチの正しさの保証：パッチは脆弱性を塞ぐだけでなく、既存機能、性能、OS や外部ライブラリなどとの互換性、および可用性を壊さないことまで要求される．またパッチが新たな脆弱性を生む可能性もある．これに対し，テストは既知の攻撃例を防げることは示せても、すべての変種や未知の経路が存在しないことまでは通常証明できない．
\end{enumerate}
このうち課題3については，セキュリティなどへの要求が満たされたかどうかを，数学的に厳密に定義し検証する\ul{形式手法}が知られている．そして LLM と形式手法の併用により，高信頼なプログラム修正を目指した研究も進められている．具体的には，LLM で生成したパッチに形式検証を適用し，不具合に関する情報を LLM に入力するというフィードバックループにより，最終的に正しいパッチを作成するという枠組みを用いている．しかし形式検証はテストに比べてコストがかかるため，大量な脆弱性への適用は非現実的である．

\textbf{[本研究の着想に至った経緯]} 応募者はこれまでに下記の各技術に関する研究成果をこれまでに挙げている：ソフトウェア工学とそのセキュリティへの応用，形式検証技術，LLM 応用技術，および知識グラフ技術．特に LLM 応用技術については，成果として LLM 応用技術の基礎となる機械学習の分野で最高峰の学術論文誌 \ul{Machine Learning (impact factor=4.3)} に計12件の論文が採択されている．また形式検証技術については，成果として論文がソフトウェア工学分野で最高峰の学術論文誌 \ul{IEEE Transactions on Software Engineering (impact factor=6.28) に採択}され，その結果\ul{情報処理学会ソフトウェア工学研究会卓越研究賞を受賞}している．

これらの研究を通じて，形式検証，LLM，および知識グラフの利用により，大量のソフトウェア脆弱性への対策を実現可能であるとの見通しを得た．

このように前述の問題点の存在を認識し，各分野における研究組織の強みの活用を目指した結果，本研究の着想に至った次第である．

\textbf{[問い]} そこで本研究では，大量の脆弱性と攻撃手段に対し，LLMと形式検証による修正パッチの生成において，どの脆弱性をどのような順序で修正すれば，コストとリスクの適切なバランスのもとで，重大な攻撃を確実に遮断できるか，という問いを立てる．そのために脆弱性のトリアージ（優先順序付け）と，脆弱性間，攻撃手段間，およびパッチ間の関係性も含め，判断根拠と修正の正しさを，理解容易な説明付きで与えることを目指す．具体的には次の各「問い」の解決を目指すものとする．

\textbf{問い1：個別の脆弱性と攻撃手段に対し，重要度や到達可能性など各種の要因を，根拠追跡可能な形でトリアージできるか}

既存のCVSS等では，脆弱性そのものの一般的な重大度は評価できるが，実環境での危険性は，当該コードが実際に実行されるか，外部入力からそのコードまで到達可能か，成功した場合に何が侵害されるか，などによって大きく変わる．そのため単なる優先順位付けではなく，たとえば「重大度Criticalだが、認証後の管理者しか到達できない」脆弱性と、「重大度Mediumだが、インターネットから認証なしで攻撃可能」な脆弱性のどちらを優先するべきか、という判断を形式化する必要がある．加えて判断根拠をどのように明確化するかも重要である．

\textbf{問い2：連鎖的な攻撃に関わる複数の脆弱性間の関係に基づいて，それらのトリアージと適切な修正計画生成は可能か}

連鎖的な攻撃への対応については，従来のトリアージのように単に脆弱性の間の優先順位だけではなく，脆弱性間の関係として，関わるコード間の呼び出し関係，攻撃の実行順序，あるいは攻撃による権限昇格の詳細なども考慮しなければならない．その上で適切な脆弱性の絞り込みや，修正順序も含めた修復計画の生成が必要である．

\textbf{問い3：トリアージに基づいて選定された脆弱性に対するパッチを，可能な限り正しさが保証した上で確実に生成できるか}

個別の脆弱性については，LLM と形式検証器とのフィードバックループにより，正しい修正パッチを作成する技術は確立されている．しかし LLM の信頼性の低さと，形式検証の計算コストの課題により，トリアージにより絞り込まれたとしても，なお大量の脆弱性をすべて修正するのは非現実的である．そのため，たとえば複数の類似した脆弱性については，1件修正できればそれらの脆弱性すべてを同様に低コストで修正する，などの対応が必要である．

\textbf{問い4：複数パッチの関係性を明確にした上で，コストとリスクの適切なバランスの考慮の上で，重大な攻撃を確実に遮断するために必要な修復計画を生成できるか}

複数のパッチ間には，修復計画を生成するために考慮すべき様々な関係性がある．たとえばあるパッチを適用するには別のパッチが必要であるという依存，複数パッチを同時には適用できないという競合，あるパッチを適用すれば別のパッチが不要になるという包摂，そして1つのパッチで複数脆弱性を修正する効果の共有などがある．このような関係性を明確にした上で，コストとリスクを可能な限り正確に算出して，適切なバランスを考慮する必要がある．

\textbf{問い5：自動生成されたトリアージ・パッチ・修復計画について，人間が理解容易な根拠を提示できるか}

問い1〜4への対応により，トリアージ・パッチ・修復計画が，明確な根拠のもとで得られるが，その根拠の多くの部分は，LLM や検証器が内部で扱う形でしか得られない．そのためたとえばユーザが根拠について自然言語で問い合わせた際に，自然言語と可視化された図などの表現により，ユーザが理解容易な回答が得られることが必要である．
	
\noindent\textbf{(2) 本研究の目的および学術的独自性と創造性}

\textbf{[本研究の目的]} 本研究の目的は，複数脆弱性，複数の攻撃手段，及び複数パッチの依存関係を考慮した修復意思決定の基礎理論を確立し，脆弱性トリアージと証明付き自動修復を統合するオントロジー駆動型知識基盤を構築することである．具体的には，以下の4つの研究目標を達成する．
\begin{description}
\item[目標A：] 脆弱性，攻撃前提・効果，資産，ソフトウェア構成，観測時刻，情報源を統合するオントロジーを設計し，その上で複数脆弱性及び複数パッチの依存関係を表すトリアージパッチ知識グラフ（Triage and Remediation Knowledge Graph; TRKG）を構築する．

\item[目標B：] 脆弱性の攻撃経路上の役割と文脈を反映し，結論から証拠まで逆追跡できる知識グラフ型トリアージ推論を確立する．

\item[目標C：] トリアージパッチ知識グラフと，複数の類似した脆弱性を修正可能な「修正パターン」を用いて，証明付きパッチの効率的かつ高精度な生成を行う．

\item[目標D：] トリアージパッチ知識グラフを用いて，すべての重大な攻撃経路を遮断することが検証可能な，最小かつ十分な修復計画を，説明可能な形で生成する．
\end{description}

\textbf{[学術的独自性]} 本研究の独自性は次の通りである．下記の (3) に示すように，前述した個別の研究目標を扱う研究は近年増加している．一方本研究は，LLM，オントロジー，および形式検証を統合したフレームワークに基づくことによる全研究目標の達成により，大量かつ相互に関連する脆弱性と攻撃手段に対し，正しさが保証された修正を，コストとリスクの適切なバランスの上で実現し，重大な攻撃を確実に遮断することを目指すものである．

\textbf{[創造性]} 本研究の創造性は次の通りである．まずトリアージについて，個別脆弱性の重大度評価だけでなく，複数脆弱性が構成する攻撃経路上の役割も考慮して行う．次に攻撃に関する知識だけでなく，パッチの前提・順序・代替・訂正・競合まで同一の知識グラフに統合し，攻撃と修復の双方の依存関係を統一的に推論可能にする．さらに LLM によるパッチ生成を1回限りのコード生成とせず，修正パターンとその適用条件を再利用可能な知識として蓄積し，形式検証で裏付ける．
